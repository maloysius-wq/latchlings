## Implemented rules

- Start with 20 energy, cap 20; regenerate one per 15 minutes. A new attempt spends one on its first valid move, not on preview, blocked input, selection, reload, or resuming a paid attempt.
- Start with zero coins. First/improved star tiers earn 10/20/30 cumulatively, paying only the improvement delta; already-accounted replays earn 2/4/6. For example: first one-star10, improvement to three-star20, three-star replay6, total36.
- Explicitly confirmed, successfully presented current-state hints cost15. Canceled, stale, impossible, inconclusive or unpresentable results are free; a paid hint for the same board reopens free.
- Explicitly confirmed +5-move continuations cost40, preserve the live board and total moves, and spend no energy. Stars still use original authored thresholds. No Undo, payments, ads or narration playback.

## Persistence and recovery

Native IndexedDB transactions serialize wallet, attempt, purchase and receipt operations across tabs. A move has prepare/animation/commit boundaries; canceled animation cannot settle a new board or award a win. Selection is persisted separately without charging. Coin awards and reward receipts commit together before legacy campaign/Daily progress delivery; interrupted delivery retries without paying again.

Existing progress seeds the accounted-tier ledger without retroactive awards. Version1 backups preserve wallet balances, recharge timestamps and prior claimed tiers; imported historic tiers are accounted, not newly rewarded. Version2 explicitly replaces the validated wallet and saved attempt after confirmation. Import uses a durable roll-forward journal spanning IndexedDB and legacy localStorage; unfinished recovery blocks play, offers retry, and exports a coherent original snapshot. Resetting campaign never refills energy or recreates first-clear payouts. Missing/unsupported storage and malformed wallets fail visibly rather than minting a replacement wallet. This is local single-device storage, not tamper-proof server currency; a user can deliberately roll back a wallet using a version2 backup or developer tools.

## Failures investigated during implementation

- Actual animation cancellation required keeping last-settled moves, not the old fixture's pre-animation counter assumption. A canceled final animation pays nothing.
- A replaced Hint-search dialog could charge for a result the player could not see. Purchase now requires the specific still-current search dialog through commit.
- Recovery could reopen a dismissed dialog after an asynchronous read. Refresh is now tied to the original visible dialog and generation.
- Cursor selection after a move was lost on reload. A serialized, stale-guarded SELECT transition now persists it free.
- Backup validation accepted arbitrary Daily tier markup. Only the eight authored tier labels are accepted.
- A test server returned404 for directory iframe URLs. Its directory-index mapping was corrected; no runtime fallback or porch assertion was weakened.
